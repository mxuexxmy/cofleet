按 [技术选型与原型验证](technology.md) 验证 Rust 后台服务、轻量托盘及微服连接。三平台分别记录运行结果和资源占用，尚未验证的平台不得标记通过。

## 阶段 0：盘点与通信验证

本地 omarchy 已完成设备服务注册、微服回调、鉴权负向测试、断线恢复、客户端内核重启及跨微服账号上下文切换，详见 [实机记录](stage0-omarchy.md)。按当前要求先验证本机；WSL2 和其他电脑仍待测，整个阶段尚未关闭。

- 记录微服系统、客户端版本和各电脑的系统、架构、资源及在线安排。
- 在一台电脑启动最小 Agent 回环接口，尝试通过现有客户端注册本地服务。
- LC 02 管理应用校验归属，取得设备入口并读取 Agent 状态。
- 验证断线、客户端重启、账号切换，以及 WSL2 服务可达性。

验收：LC 02 可经现有懒猫设备通道读取指定电脑上的测试服务；未授权访问失败；记录真实版本与限制。不把编译成功当作通信已验证。

设计基线见 [专项方案](docker-observe-access.md)。M1/M2 与自动前缀访问已集成进主工作台，本机 HTTP、Cookie 登录及 WebSocket 已验证，详见 [0.7.2 整合记录](access-integration.md)。当前采用受信任应用模式，共享父域普通 Cookie 的限制保留；不再以独立 Cookie Site 为唯一上线方式，也不把前缀独立来源视为完全站点隔离。

## 当前优先路线：长期在线与入口可靠性（0.8.0）

按以下顺序实现，详细契约和验证记录见 [长期在线与入口可靠性](agent-reliability.md)：

1. **Agent 用户级自启动**：Linux systemd 当前用户安装、状态、日志、启停、升级与卸载；稳定安装路径，保留原 data-dir 和全部能力开关，失败升级回退旧执行文件。不启用 root 服务或 linger。Windows 用户启动脚本补齐观察开关，Windows 实机待验收。
2. **离线设备持久化**：按账号保存最近设备快照，管理中心重启后恢复为离线；原设备重连合并同一记录。资源注明采集时间和过期状态，控制会话不持久化。数据库损坏明确失败，不静默清空。
3. **入口操作可靠性与环境识别**：超时先核对结果，沿用入口 ID／revision 重试；待确认操作互斥，账号切换清除本页状态并隔离旧响应。Docker 引擎指纹变更撤销旧绑定，重新发现并确认后保留原 URL；引擎不可用不使整个 Agent 下线。

下一轮按真实使用反馈完善更多应用和 Windows／WSL 实机验证，继续保留第二账号、平台侧撤销、跨网与容量测量的待验收项。调度仍仅生成计划，不自动执行。
