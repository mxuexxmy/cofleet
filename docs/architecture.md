# 架构与通信设计草案

以下为设计草案。Linux Agent 与微服测试版的真实登录、WSS 控制与重连已验证；执行环境和设备服务网关等其余部分仍待实测。部署结果见 [验证记录](deployment/lazycat-validation.md)。

## 职责

```text
随身电脑 / 浏览器
        |
LC 02：管理 API、期望状态、调度、访问入口
        |
懒猫现有网络与设备通道
        |
电脑 Agent → 执行环境 → 工作空间 / 任务 / 应用
```

管理中心只承担轻量管理，但采用反向代理时仍承载业务流量。不能假设已有设备通道意味着浏览器流量自动绕过 LC 02。

## 电脑端进程边界

- Agent 为独立后台服务，承担设备连接、资源上报和已授权的任务操作。
- 托盘为用户会话中的轻量进程，通过受操作系统权限约束的本地 IPC 获取状态和提交有限操作，不直接持有后台服务的高权限。
- 退出托盘不停止 Agent；暂停接收新任务不终止已有任务。停止后台服务使用单独的明确操作。
- 首次连接、本机授权和断线诊断需有离线可用的本地入口；日常管理优先使用微服 Web 页面。
- Windows 服务、macOS 后台服务及 Linux systemd 分平台适配；Linux 无桌面环境时允许仅运行 Agent。

具体设置入口、IPC 与安装方式在原型中验证，尚未实现。

## 借鉴 Kubernetes

1. **期望状态与实际状态分离**：管理中心持久保存用户目标，Agent 上报实际状态，控制循环安排必要操作。
2. **幂等执行**：部署标识、配置版本和操作标识用于去重，连接超时后的重试不重复创建实例。
3. **节点自治**：管理中心短时离线时，已有负载继续运行，本地按已授权策略重启；恢复后核对状态。
4. **资源预算**：调度基于可分配资源、已承诺资源、能力标签和数据位置，不只依据瞬时利用率。
5. **区分未知与停止**：心跳超时不能证明旧实例停止。数据库等有状态负载默认不跨节点自动接管。
6. **计算与数据分离**：卷记录所属节点、用途和保留策略；调度遵守数据位置约束。
7. **稳定入口**：应用入口关联当前健康实例，运行位置可变化，但连接和桌面会话不承诺无缝迁移。

第一版可由单进程承担 API、控制循环和简单调度。运行语言首选 Rust，待原型验证；状态存储及后续编排后端尚未选型。

## 通信参考

### lzc-mesh：主动连接中枢

已读源码显示，原生客户端读取懒猫客户端本地接口配置，经 `/default-box`、`/box-ext-info` 获取连接和会话信息，携带登录 Cookie 连接微服应用 `/api/ws`，通过 JSON 消息交换状态和事件。中枢依赖可信平台入口提供的用户身份隔离设备组。

可借鉴用于节点注册、心跳、资源上报、任务通知和日志流。项目还有独立的局域网 QUIC 直连机制；它不等同于通用跨网设备端口直连。

### lightos-remote-desktop：设备服务网关

已读源码显示，Agent 经客户端本地 Shell API 调用 `LocalServiceGateway/RegisterLocalService`，注册指向本机回环端口的 HTTP 服务，再向微服管理应用登记和续期。

管理端校验设备归属及在线状态，取得平台返回的 `DeviceApiUrl` 和设备访问令牌，访问 `<DeviceApiUrl>/s/<service>/...`。本机控制服务还使用自身随机凭据。桌面主要路径由微服管理服务反向代理 HTTP/WebSocket 到已注册服务。

可借鉴用于受控管理接口和 Web 应用入口。不能推断客户端支持任意未经注册的端口，也不能将仓库实现视为全部已安装客户端版本的兼容保证。

### CoFleet 待验证选择

控制面已参考 lzc-mesh，选择 Agent 主动发起的 WSS 中枢连接；本机原型已实现 `/api/ws`、注册、心跳确认和中枢请求上报。开发模式使用测试凭据，实验懒猫模式对接本机登录会话及可信入口身份，按账号隔离节点。

设备回环服务网关仍是后续工作空间与应用访问的候选数据路径，不作为控制面建立连接的前提。需继续验证实际客户端登录、WSS 入口及设备服务可达性；详情见 [lzc-mesh 架构对应](lzc-mesh-reference.md)。

普通 HTTP 服务可参考懒猫内外网上游代理；TCP/UDP 可参考平台四层转发。四层转发本身不提供 HTTP 用户鉴权，目标协议必须自行认证。WSL2 服务到 Windows 客户端网关之间的连接需单独验证。

## 核心对象草案

| 对象 | 职责 |
| --- | --- |
| Device | 物理设备身份、归属、在线状态和资源预算 |
| ExecutionEnvironment | Device 下的系统、WSL2 或容器运行环境及能力 |
| Workspace | 持久开发环境和项目位置 |
| Task | 有明确输入、输出和重试规则的工作 |
| Application / Instance | 应用目标及其具体运行实例 |
| Volume | 数据位置、访问方式和保留策略 |
| Endpoint | 可访问入口及对应的健康服务 |

对象名称与字段尚未冻结，不构成 API 规范。

## 授权与故障边界

- 区分用户身份、设备身份、Agent 授权；不能信任节点自报的归属。
- 登录令牌不写入日志、普通元数据或仓库；不把关闭 TLS 验证当作默认实现。
- Agent 是高权限边界：仅提供明确的管理动作，不公开无认证 Docker API。
- 节点离线后暂停新派单；任务允许重试前先判断重复执行影响。
- 有状态单实例接管需可靠隔离旧写入者；第一版默认等待原节点恢复。
- 删除应用默认保留持久卷，具体删除需显式选择。
