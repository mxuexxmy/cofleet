# 实施路线与验收

## 阶段 0 前置：技术原型

按 [技术选型与原型验证](technology.md) 验证 Rust 后台服务、轻量托盘及微服连接。三平台分别记录运行结果和资源占用，尚未验证的平台不得标记通过。

## 阶段 0：盘点与通信验证

- 记录微服系统、客户端版本和各电脑的系统、架构、资源及在线安排。
- 在一台电脑启动最小 Agent 回环接口，尝试通过现有客户端注册本地服务。
- LC 02 管理应用校验归属，取得设备入口并读取 Agent 状态。
- 验证断线、客户端重启、账号切换，以及 WSL2 服务可达性。

验收：LC 02 可经现有懒猫设备通道读取指定电脑上的测试服务；未授权访问失败；记录真实版本与限制。不把编译成功当作通信已验证。

## 阶段 1：指定节点管理

- 已实现：展示 CPU、内存、Agent 所在文件系统、系统与 WSL 标识；通过本地命令设置预留并持久化。
- 展示 Docker 容器，启动和停止一个受管测试容器，读取日志。
- 保存期望状态，验证重试去重、重启恢复及显式停止行为。

验收：一次请求超时再重试不产生重复实例；管理中心断开不导致现有容器停止；节点恢复后状态正确。

## 阶段 2：持久开发空间

- 选择一种开发接入方式，在资源充足的电脑创建工作空间。
- 绑定项目卷，提供稳定入口和服务健康状态。
- 关闭页面、更换终端或网络后重新进入。

验收：代码与依赖仍在，已有服务按策略运行；从外网完成实际编辑、终端操作与调试。记录 LC 02 代理资源开销和实际网络体验。

## 阶段 3：构建到部署

- 固定代码提交或输入快照，提交构建任务。
- 保存日志及产物版本，部署明确镜像版本。
- 更新前检查健康，保留上一版本信息；数据迁移不能仅靠镜像回滚处理。

验收：低性能电脑可完成远程开发、构建、部署并访问应用的完整闭环。

## 阶段 4：多节点协作

- 增加第二个执行节点及简单资源调度。
- 加入数据位置、GPU 能力及长期在线偏好。
- 按负载类型实现等待、重试或重建策略。

验收：调度不重复计算物理资源；缺少匹配节点时明确显示原因；有状态负载失联不被盲目复制。

## 当前状态

已实现阶段 0 前置的本机连接原型：Rust WebSocket 中枢、Agent、命令行和托盘；Linux 闭环与托盘菜单操作验证通过。原型暂不执行实际任务，暂停/恢复仅保存和上报接收新任务的意图。

已参考 lzc-mesh 增加实验懒猫登录适配、可信入口身份和按账号隔离，并用模拟客户端/Ingress 测试；阶段 0 的真实登录、WSS 控制和重连已在默认微服测试版验证；设备服务网关验证仍待执行。Windows/macOS 实机验证、后台服务安装验证及 10 分钟以上资源基线尚未完成，无生产部署或跨平台性能承诺。

0.2.0 已完成阶段 1 的资源可观测性与预留规划。Docker 容器操作、任务执行、期望状态持久化仍未实现，不将本机预留规划视为强制资源隔离。
