# 产品构思

更新日期：2026-11-06。

## 名称与定位

- 中文项目名：聚机。
- 英文项目名：CoFleet。
- 功能描述：懒猫协同电脑。
- 标语：让你的电脑一起工作。

聚机连接用户已有的电脑，统一提供开发、构建和部署能力。它不替代用户已有的懒猫算力设备，名称和产品描述不以“算力”作为核心定位。

## 适用场景

将一台微服作为管理中心，连接多台性能、存储与在线安排不同的电脑。在家或出门时，通过性能较弱的随身电脑使用工作节点上的持久开发环境，充分利用已有设备。

设备系统、CPU 架构、GPU 型号、可长期在线时间，以及微服和客户端版本，尚待盘点。不能将现有网络体验直接视为所有协议、端口与访问方向均已验证。

## 三个核心工作对象

### 工作空间

保存代码、工具链、依赖、终端服务和持久目录。第一版绑定明确的执行环境和数据位置，支持离开后再次访问。关闭浏览器不等于销毁环境；明确停止意图需要持久保存。进程或电脑重启后不能承诺恢复任意内存状态。

当前以每设备一个 code-server 持久开发空间提供浏览器 IDE 与项目预览；项目数据保存在节点命名卷中。

上述选择仍针对工作空间。对于物理机，2026-11-04 已确定不在 CoFleet 内实现 Shell 或远程桌面数据面：Shell 依赖 LCMD WebShell，桌面依赖懒猫远程。0.8.1 已提供“物理机工具”中的应用级入口，由上游选择设备；未配置时显示依赖说明，终端／桌面的 P0 实机验证仍待完成；设备级精确跳转等待公开、稳定的跨应用设备身份契约。研究结论和验收门槛见[物理机终端与远程桌面依赖集成](physical-machine-remote-access.md)。

### 任务

具有确定输入、资源要求、状态、日志和输出，例如构建、测试、转码。优先用代码提交或输入快照保证可重现，不让构建依赖持续变化的开发目录。

### 应用

记录镜像版本、部署节点、配置、数据卷、健康状态和访问入口。开发预览与长期部署分别管理；继续修改代码不应自动改变已部署版本。

## 已有 Docker 应用的观察与访问（2026-11-04 补充）

对于已经由 1Panel、Compose 或其他工具部署的应用，CoFleet 新增方向限定为只读发现、状态与日志查看，以及用户手动配置的统一访问入口。部署、启动停止、升级和数据管理继续在原工具中进行，不导入或接管原部署配置。

该方向与 CoFleet 自有开发空间及构建发布并存，观察接口不提供外部容器变更操作。删除入口不删除应用。0.7.2 已把只读发现、日志、SQLite 入口库及自动前缀访问整合进主工作台，验证了本机 HTTP、应用登录和 WebSocket。当前采用用户主动添加的受信任应用模式：每个入口有独立来源，但共享父域的普通 Cookie 污染风险仍存在；不能宣称完全站点隔离。入口授权绑定当前账号、浏览器、入口版本和 Agent 会话。第二真实账号及更多真实项目仍待验收。设计边界见 [专项方案](docker-observe-access.md) 和 [访问整合记录](access-integration.md)。

## 设备与执行环境

物理电脑是资源预算边界；WSL2、Docker 等是其下的执行环境。多层上报不得重复累计同一份内存、CPU 或 GPU。用户可设置预留资源、允许任务类型以及是否接受自动调度。

## 初期边界

- 支持有限的容器开发和应用场景，不承诺远程运行任意商店 LPK。
- 不做透明跨机内存、显存合并或运行中进程无缝迁移。
- 不以第一版实现分布式存储或多控制中心高可用。
- 不修改懒猫客户端或另建网络核心作为默认前提。
- 保留用户选择设备的能力，自动调度逐步加入。

## 首个用户故事

使用低性能电脑打开聚机，在资源充足的工作节点上创建持久开发空间；关闭页面、换网络或换电脑后继续同一个项目，将确定版本构建并部署为可访问的应用。

## 设备长期可用与入口可靠性（0.8.0）

优先保证电脑登录后能持续被看到，再保证离线记录和入口操作可恢复。Linux 提供当前用户的 systemd 自启动，不要求 root、不自动启用 linger；这意味着用户登录后启动，不能等同于无人登录开机运行。升级保留节点身份、配置、能力开关及项目数据；卸载自启动仅移除服务注册。懒猫认证仍依赖本机客户端的登录上下文。Windows 用户登录启动脚本补齐 Docker 观察开关，实际生命周期仍待 Windows 实机验证。

管理中心持久保存账号内设备的最近快照。重启后离线设备仍可查看名称、系统与最后资源信息，但明确标为离线；最后一次资源值不冒充实时值。控制连接、访问会话和操作中的请求不从数据库恢复，在线后由原设备身份重新登记。

入口创建、启停、删除或重新绑定遇到超时时，界面保留本次请求并提供“核对并重试”；先查询服务端结果，再以原 ID 或原 revision 重试，避免重复创建或覆盖后续修改。待核对期间阻止新的入口写操作；切换账号和退出会清除本页草稿与待确认操作，旧账号响应不能进入新界面。待确认请求只保存在当前页面内，不承诺刷新页面后继续恢复。

Docker 环境由本地固定 socket 与引擎身份共同识别。引擎不可用时只禁用观察和入口能力，Agent 保持连接。环境变化后旧授权失效，用户重新发现并明确确认目标才能恢复；重新绑定保留入口 URL。首次升级到引擎身份版本也需要重新确认旧入口，不自动追随同名容器或另一个 Docker daemon。

实施、命令与验证边界见 [长期在线与入口可靠性](agent-reliability.md)。
