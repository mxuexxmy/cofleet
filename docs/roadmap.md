# 实施路线与验收

## 阶段 0 前置：技术原型

按 [技术选型与原型验证](technology.md) 验证 Rust 后台服务、轻量托盘及微服连接。三平台分别记录运行结果和资源占用，尚未验证的平台不得标记通过。

## 阶段 0：盘点与通信验证

本地 omarchy 已完成设备服务注册、微服回调、鉴权负向测试、断线恢复、客户端内核重启及跨微服账号上下文切换，详见 [实机记录](stage0-omarchy.md)。按当前要求先验证本机；WSL2 和其他电脑仍待测，整个阶段尚未关闭。

- 记录微服系统、客户端版本和各电脑的系统、架构、资源及在线安排。
- 在一台电脑启动最小 Agent 回环接口，尝试通过现有客户端注册本地服务。
- LC 02 管理应用校验归属，取得设备入口并读取 Agent 状态。
- 验证断线、客户端重启、账号切换，以及 WSL2 服务可达性。

验收：LC 02 可经现有懒猫设备通道读取指定电脑上的测试服务；未授权访问失败；记录真实版本与限制。不把编译成功当作通信已验证。

## 阶段 1：指定节点管理

- 已实现：展示 CPU、内存、Agent 所在文件系统、系统与 WSL 标识；通过本地命令设置预留并持久化。
- 已实现：展示 Docker 容器，启动和停止一个受管测试容器，读取日志（原生 Linux，需显式启用）。
- 已实现并实测：节点持久化期望状态和请求 ID，验证重试去重、Agent 重启恢复及显式停止行为。

验收已在 omarchy 原生 Docker 通过：一次请求超时再重试不产生重复实例；管理中心断开不导致现有容器停止；节点恢复后状态正确。详见 [阶段 1 实机记录](stage1-docker.md)。WSL2 后续待测。

## 阶段 2：持久开发空间

- 已实现：code-server 浏览器接入，在 omarchy 原生 Docker 创建限额开发空间。
- 已实现：节点命名卷持久保存项目、依赖与编辑器数据，提供按设备 ID 的稳定入口及编辑器/项目健康状态。
- 已实测：关闭页面、更换终端和管理连接重建后进入同一空间；独立外网设备和实际异网切换待测。

开发已完成，本机与真实微服域名链路已验证：代码、依赖与项目脚本恢复策略生效，完成编辑、终端与调试，记录 LC 02 代理开销。当前没有独立外网设备，不将同一网络下访问微服域名当作完整外网验收。详见 [阶段 2 记录](stage2-workspace.md)。

## 阶段 3：构建到部署

- 已实现：冻结工作空间输入快照并记录 SHA-256，提交异步构建任务。
- 已实现：保存任务日志与不可变镜像 ID，以请求 ID 去重并按预期当前版本发布。
- 已实现：候选健康后切换，保留上一版并支持回滚；首版拒绝有状态及数据迁移发布。

开发及原生 Docker 闭环已验证，详见 [阶段 3 记录](stage3-pipeline.md)。低性能实体电脑、独立外网设备与 WSL2 的实机验收仍待测。

## 阶段 4：多节点协作

- 已实现调度核心与管理界面；本机和微服已更新 0.6.0，第二台 Windows Agent 已在线注册，执行器仍待启用实测。
- 已加入物理主机去重、数据位置、GPU 能力及长期在线偏好。
- 已按负载类型实现等待、重试或重建决策；具体任务仍沿用节点侧幂等接口。

自动化验收已通过：调度不重复计算物理资源；缺少匹配节点时明确显示原因；有状态负载失联不被盲目复制。第二台实体 Windows 节点的 SCM、Docker Desktop 和断网闭环仍待实机验收，详见 [阶段 4 记录](stage4-multinode.md)。

## 后续专项：已有 Docker 应用观察与统一访问

设计基线见 [专项方案](docker-observe-access.md)，新增能力尚未实现，不替代阶段 0–4 的待完成验收。

1. **M0：域名与鉴权验证**。先验证独立来源、平台登录、第三方应用 Cookie／Authorization、重定向和 WebSocket；未通过时不开放通用应用访问。
2. **M1：只读发现与日志**。独立启用观察能力，增加分页容器发现、Compose 分组、端口候选和有界日志，不提供外部容器变更操作。
3. **M2：持久入口闭环**。保存入口配置，按容器／服务身份核对端口，验证原工具重建、端口复用、重启恢复、跨账号隔离与删除入口不影响原应用。
4. **M3：平台与应用适配**。逐步实测 Windows Docker Desktop／WSL 和更多应用；其他协议与深入管理另行设计。

## 当前状态

已实现阶段 0 前置的本机连接原型：Rust WebSocket 中枢、Agent、命令行和托盘；Linux 闭环与托盘菜单操作验证通过。0.3.0 增加固定测试容器执行；暂停会拒绝新的测试容器启动意图。

已参考 lzc-mesh 增加实验懒猫登录适配、可信入口身份和按账号隔离，并用模拟客户端/Ingress 测试；阶段 0 的真实登录、WSS 控制和重连已在默认微服测试版验证；设备服务网关已在本地 omarchy 与真实微服之间验证，结果和鉴权限制见 [阶段 0 实机记录](stage0-omarchy.md)。Windows/macOS 实机验证、后台服务安装验证及 10 分钟以上资源基线尚未完成，无生产部署或跨平台性能承诺。

0.2.0 已完成阶段 1 的资源可观测性与预留规划。0.3.0 已完成原生 Linux 固定测试容器操作和节点期望状态持久化，不将本机预留规划视为强制资源隔离。

0.4.0 已实现每节点一个持久开发空间和独立反向 WSS 数据通道；完整异网验收待有可用设备后补测。

0.5.0 已实现指定节点的输入快照、构建日志、不可变镜像发布、健康切换与回滚；当前仅支持无状态 HTTP 应用。

0.6.0 已实现多节点调度核心、物理主机资源去重、能力/数据约束、故障策略和 Windows SCM Agent；第二台实体 Windows Agent 已在线注册，执行器和断网闭环仍待验收。
