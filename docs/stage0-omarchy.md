## 通信链路

在 omarchy 的随机 `127.0.0.1` 端口启动临时只读 HTTP 服务，通过 IPC 读取正在运行的 Rust Agent 状态，并使用现有懒猫客户端的 `RegisterLocalService` 注册。微服应用容器内运行独立探针，按账号查询平台设备目录，匹配在线设备、取得真实设备入口，再请求设备授权令牌并经 `/s/<随机服务名>/status` 回调。

实际收到的随机挑战值和 Agent 设备 ID 均与本机预期一致。设备 TLS 证书校验保持开启；没有使用跳过校验的 SDK 客户端构造器。HTTP 测试移除客户端证书，避免把证书认证误当作请求凭据认证。

这是**应用容器中的阶段 0 诊断链路**，尚未把设备服务注册和回调集成进产品的长期运行逻辑；现有产品的 WSS 通道继续运行。该探针不能执行远程命令或任务。

## 实测结果

| 检查 | 结果 |
| --- | --- |
| 归属查询、在线设备匹配 | 通过 |
| 设备令牌获取、带凭据回调、挑战值与 Agent 状态校验 | 通过 |
| 匿名请求 | HTTP 403 |
| 错误平台令牌，无接口密钥 | HTTP 403 |
| 错误接口密钥，无平台令牌 | HTTP 403 |
| 仅平台令牌，无接口密钥 | HTTP 403 |
| 仅正确接口密钥，无平台令牌 | HTTP 200；见鉴权限制 |
| 不存在账号查询目标设备 | 归属被拒绝；未继续回调 |
| 禁用当前微服连接，再启用 | Agent 观察到断开并恢复，设备 ID 不变 |
| 懒猫客户端内核终止与恢复 | 内核 PID 改变；短时 CLI 旧端口不可用，随后客户端、CLI 和 Agent 恢复 |
| 切换已登录的另一个微服账号上下文 | 原 Agent 断开；恢复原默认微服后重新连接，设备 ID 不变 |

账号切换是两个已登录微服、两个不同用户之间的默认上下文切换，没有退出登录、修改密码或删除凭据。它验证了原管理地址不能使用另一个默认微服的登录态；不等同于同一微服上的两个用户互换登录，也不证明所有跨账号场景。

内核重启测试早期读取到的 `connected` 可能是尚未刷新的状态，因此不能只用一次即时读取作结论；最终以 CLI 恢复、Agent 持续更新和重新注册后的微服真实回调共同判断。

## 鉴权发现与限制

注册接口中的 Header 名和值用于向后端**注入**请求 Header。若用它直接承载接口密钥，匿名请求也会获得密钥，产生错误的“鉴权通过”结论。本轮修正为独立的网关标记 Header，接口另行验证调用者传入的随机 `X-CoFleet-Probe-Key`，再完成上述负向测试。

当前环境中，正确接口密钥可独立访问该 HTTP 服务；平台令牌不是该服务的强制第二重门槛。未来长期接口必须保留独立认证、可信账号来源和归属校验，不能依赖服务名隐藏或 Header 注入来保护任务执行。
