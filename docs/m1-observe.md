# M1：只读 Docker 资源与日志验收

记录日期：2026-11-04（Asia/Shanghai）。本轮补全 0.7.0 已有观察接口的界面和边界处理；已随后部署 0.7.0 到懒猫微服，未修改现有 Agent 配置。部署验证发现并修复普通开发空间／应用隧道在取消通道关闭后被误关的回归；编辑器、项目预览及已发布应用的真实访问均通过。

## 使用方式

在目标 Linux 电脑本机为 Agent 添加 `--docker-observe`，不要求同时启用 `--docker` 测试执行器。打开管理端“应用入口”，选择电脑并点击“读取容器”。

- 列出所有容器，包括已停止、未发布端口和没有 Compose 标签的容器。
- 按 Compose 项目分组，展示服务、镜像、运行与健康状态、已发布 TCP 端口及转发限制。支持名称／镜像／项目／ID 搜索和运行状态筛选。
- 每个容器可独立查看日志，无须先创建入口。可选最近 100／300／500 行，返回最多 16 KiB，超出显示截断标记与采集时间。两条 Docker 输出流均持续读取，只保留有界末尾；stdout、stderr 合并不保证严格时间交错。
- 容器目录与日志由用户手动刷新，设备连接仍每 5 秒刷新。自动刷新保留搜索、端口选择、日志展开及滚动；切换设备显示所属设备的数据，退出清空内存状态并取消请求。
- 离线、连接待确认、旧 Agent 或未启用观察时，展示原因并禁用读取。读取失败保留上次成功快照，界面明确标记上次读取时间。

## 实现边界

观察只使用固定本机 Docker 地址与 `ps`、`inspect`、`logs` 参数，不执行 shell 或容器修改。inspect 模板只读取所需字段，不读取 env、挂载和健康检查日志。常规错误不回传原始 stderr，避免泄露应用内容。

目录每页最多 50 个容器，同时按序列化字节数限制页面，以免长名称或转义字段超过传输上限。快照游标有效期 15 秒，过期需重新读取；超过 500 个容器明确报错，避免静默遗漏。观察结果不写入心跳、数据库或常规日志。单次结果 128 KiB；日志限制为 16 KiB，为最坏 JSON 转义保留余量。

## 验证

- `cargo test --locked --lib --test ws_hub`：26 个单元测试、4 个协议集成测试通过，覆盖账号隔离、旧会话和有界日志读取。
- `cargo clippy --locked --all-targets -- -D warnings` 通过。
- `tests/observe_native.py`：临时管理中心及 Agent，针对本机现有容器真实读取；9 组检查通过。目录逐项分页与 Docker 全量 ID 一致，日志有界，无效 ID／消失容器／无效游标被拒绝，未授权访问被拒绝，关闭观察后 409，测试前后容器名称、状态及端口一致。测试 Agent 使用只允许 ps／inspect／logs 的 Docker 包装器，原有进程不受影响。
- 故障模拟覆盖空目录、超过 500 个容器、权限不足、Docker 不可用、日志驱动不支持，以及大量中文 stderr。故障模拟与真实 Docker 读取分别记录，未伪称这些故障发生于生产环境。
- `tests/manager_ui.mjs`：浏览器回归通过，补充 Compose 分组、无端口容器日志入口、筛选无结果、设备间日志隔离、搜索跨刷新保留、日志请求跨刷新完成及退出清理；1440／1024／390px 截图与水平溢出检查。
- `tests/scheduler_ui.mjs`：现有调度交互回归通过。
- `python3 tests/smoke.py`：进程级 smoke 通过。

复现：先 `cargo build --locked --bins`，再 `python3 tests/observe_native.py`。浏览器脚本使用环境中的 Playwright；输出位于 `.local/ui-preview/redesign/`，原生测试结果位于 `.local/observe-tests/<run>/results.json`。不提交真实应用日志、身份凭据或本机目录快照。
